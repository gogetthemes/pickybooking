Booking flows

Four wizard modes share the same engine — availability, buffers, payments — but change the order guests experience.

Choose a mode

ModeBest whenGuest path
Classic Map is the hero; guests know where they want to sit Item → date/time → details → book
Smart Time scarcity matters more than specific seats Date/time → available items → details → book
Smart Map You want both map and live availability Map + dock for date/time → select → tray → book
Simple Few identical resources; map is optional Date/time → details → auto-assign free item

Set the site default in Main. Override per layout in the builder.

Shared guest capabilities

Availability

Work days, horizon, duration, buffer, exclusive/capacity all apply in every mode.

Multi-select

When enabled on the layout, guests can reserve several items; creates an order + child bookings.

Services

Chips from the layout library; add-ons respect parent service rules.

Avatars

Booked seats can show the guest photo filling the tile (same size as empty seats).

Event mode

Fixed ceremony/match time — calendar UI hidden; optional label on the bar.

Payments

CTA becomes Pay & Book when a deposit/provider is required.

Guest journey (Smart Map example)

  1. Open the pageMap loads; bookable items animate in; dock shows date/time fields.
  2. Pick date & timeUnavailable seats update on the map for that slot.
  3. Select seat(s)With multi-select, items collect in the tray; otherwise one selection opens the form.
  4. Add services & contactsOptional party size, email, phone, consent.
  5. Book or paySuccess screen / Stripe or Woo redirect → confirmation emails/SMS/webhooks.

Mobile

Configure whether phones keep a scaled map, hide the map, or use a dropdown of items. Always test the chosen wizard on a real phone width.
